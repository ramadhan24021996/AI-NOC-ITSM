## 2. SPESIFIKASI ARSITEKTUR ENGINE & INTENT ROUTING

Gemini 3.6 Flash beroperasi pada **Layer 4 (Python AI Core Engines)** dan terhubung secara seamless dengan **Layer 2 (API Gateway)** serta **Layer 3 (Go Core Services)**.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                SYSTEM PORTAL WEB UI (9443)                             │
└──────────────────────────────────────────┬─────────────────────────────────────────────┘
                                           │ WebSocket / REST API
┌──────────────────────────────────────────▼─────────────────────────────────────────────┐
│                            MULTI-LLM INTENT ROUTER (llm_router.py)                     │
└────────────┬─────────────────────────────────────────────────────────────┬─────────────┘
             │ GPU Local (< 15ms)                                          │ Failover REST API (< 200ms)
┌────────────▼────────────────────────────┐                  ┌─────────────▼────────────────────────────┐
│  LOCAL MODEL: Qwen2.5-Coder / Local LLM │                  │ CLOUD MODEL: Gemini 3.6 Flash / 1.5 Pro  │
└─────────────────────────────────────────┘                  └──────────────────────────────────────────┘
```

### ATURAN MULTI-LLM INTENT ROUTING:
- **Kategori RCA & Root Cause Analysis:** Diarahkan ke engine penalaran tinggi (Gemini 3.6 Flash / Gemini Pro) untuk traversal kausalitas DAG.
- **Kategori SOP & Document Retrieval:** Menggunakan **RAG 2.0 Vector Search** (`knowledge_fabric.py`) dengan similarity search pada database `sprint_q_rag.db`.
- **Kategori Auto-Code Generation & Remediation Script:** Dievaluasi oleh **Policy Engine Safeguard** (`policy_engine.py`) sebelum diproses oleh **AI Planner**.
- **Failover Automatic Mode:** Jika GPU lokal mengalami batas kapasitas (memory pressure) atau error, routing secara otomatis berpindah ke **Gemini 3.6 Flash Cloud REST API** dalam latensi < 200ms tanpa downtime.

## 3. PROTOKOL ALUR WORKFLOW & EKSEKUSI INSIDEN

### PHASE 1: TELEMETRY INGESTION & DETEKSI ANOMALI 24/7
- **Active Observer Daemon** (`active_observer_daemon.py`) berjalan secara terus-menerus mengawasi data CPU, RAM, Disk, dan Spooler dari **Windows Agent** (`.zip`) dan **Linux Agent** (`.deb`).
- **NATS JetStream Partitioning:** Data dipisahkan berdasarkan topik lokasi multi-site:
  - `telemetry.site.<site-id>.critical`
  - `incident.site.<site-id>.create`

### PHASE 2: DIAGNOSIS & AI PLANNING ENGINE
- **AI Planner** (`ai_planner.py`) menyusun 3 pilihan skenario perbaikan:
  - **Plan A (Rekomendasi Utama):** Auto-remediation dengan dampak terendah.
  - **Plan B (Skenario Alternatif):** Tindakan pemulihan sekunder.
  - **Plan C (Fallback Emergency):** Skenario isolasi/rollback darurat.
- **Causal DAG Engine** (`causal_dag.py`) memetakan graf dependensi insiden untuk memastikan titik kegagalan utama terisolasi.

### PHASE 3: HITL SAFEGUARD & POLICY ENGINE
- Sebelum tindakan dieksekusi oleh **AI Executor** (`ai_executor.py`), **Policy Engine** (`policy_engine.py`) mengevaluasi tingkat risiko:
  - **Risiko Rendah:** Eksekusi otomatis langsung tercatat di log audit.
  - **Risiko Tinggi (P0/P1):** Ditahan di antrean **Incident Triage & HITL Queue** (`portal/dashboard/incident/incident.go`) menunggu persetujuan digital operator NOC.

### PHASE 4: EXECUTION & DOUBLE-GATE VERIFICATION
- **AI Executor** mengirimkan perintah terenkripsi AES-256 via **NATS JetStream** ke agen target.
- **AI Verifier** (`ai_verifier.py`) melakukan validasi *Pre & Post-Execution*.
- **Chaos Worker Auto-Rollback:** Jika indikator kesehatan sistem pasca-eksekusi tidak memenuhi kriteria sukses, mekanis rollback otomatis dipicu dalam kurun waktu < 5 detik.
